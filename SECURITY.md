# Security Policy

## Supported versions

EasyTrip has not cut a tagged release yet, so there is exactly one supported version: the current
`main`. Once `v1.0.0` is tagged this section will say which minor versions receive fixes.

## Reporting a vulnerability

**Please do not open a public issue.**

Use GitHub's private reporting — **Security → Report a vulnerability** on this repository — or
contact a maintainer directly via the profiles in
[the README's Contact section](README.md#-contact).

Please include what you did, what you expected, what happened instead, and the affected route or
file if you know it. A proof of concept is welcome but not required.

You will get an acknowledgement as soon as a maintainer sees the report. This is a small project
maintained alongside coursework, so please assume days rather than hours, and say so in your report
if you believe the issue is being actively exploited.

## Already known: credentials in git history

**If your finding is that this repository's early git history contains real credentials — that is
known, tracked, and does not need a new report.**

Four values were committed early in the project's life. The exposure is documented rather than
quietly ignored, and rotation is an open item on the owner. History rewriting is deliberately _not_
the plan: the affected commits have already been cloned and indexed, so rewriting would remove the
evidence without removing the exposure. Rotation is the only thing that actually closes it.

What has changed is that it cannot happen again silently: `npm run check:secrets` runs in CI and
fails the build on a tracked credential.

## What this project already does

Stated so a reviewer can check the claims rather than take them:

- **Authentication** is Firebase ID-token verification in middleware; every admin route re-checks
  the admin flag against the database rather than trusting a claim in the token.
- **Authorisation lives in SQL.** Ownership and collaborator rules are composed into the queries
  themselves — a handler-side check can be forgotten by the next caller, a `WHERE` cannot.
- **Rate limiting** is applied per route group, and `TRUST_PROXY_HOPS` is documented with the
  spoofing consequence of setting it too high.
- **Input validation** is centralised in route validators; the database additionally holds `CHECK`
  constraints on the closed vocabularies.
- **Dependency advisories** are gated in CI at **high** across all three workspaces, dev
  dependencies included — a compromised dev dependency runs on the machine holding the deploy
  credentials. The gate is not set at `moderate` because it would have been red the day it was
  added, and a gate that is red on arrival gets skipped rather than fixed. Moderate advisories are
  tracked in the docs instead of pretending to a threshold nobody would honour.
- **Secrets** are never read from anything but the environment, and the server refuses to boot on a
  missing or malformed one rather than falling back to a default.

## Scope

In scope: anything in this repository — the API, the frontend, the migrations, the CI workflows.

Out of scope: findings against a third-party service's own infrastructure (Firebase, Cloudinary,
Open-Meteo, Google Maps), and reports generated by an automated scanner without a demonstrated
impact on this application.
